# 凌川 Design 1.0 · Lingchuan Design

面向中文设计工作的一份开源技能整理与探索分支：把需求推进成可查看、可修改、可交付的视觉成果。

**基于 [花叔 Huashu Design 3.0](https://github.com/alchaincyf/huashu-design) 派生。** 原有方法、风格库、组件和工具主要来自上游；凌川 1.0 是本分支编号，当前元数据补丁版为 **1.0.1**。凌川新增“先对齐视觉参考，再探索设计方向”的前置流程，并整理能力说明和演示策划；各方向效果和新流程仍需实际任务验证。原作者版权及 [MIT 许可](LICENSE)保留。

## 能做什么

| 方向 | 任务与预期文件 | 需要实际验证的程度 |
|---|---|---|
| 网页与桌面界面 | 品牌介绍、展览、活动页、后台视觉原型；HTML 与截图 | 阅读、手机布局与必要交互，生产后端另做 |
| 手机 App 原型 | 记录、菜谱、计时等核心流程；可点击 HTML | 点击路径；不等于已上架原生 App |
| 幻灯片与提案 | 中文讲座、汇报、品牌提案；HTML deck、PDF、PPTX 路线 | PPTX 文字编辑和视觉保真逐页核对 |
| 信息图与可视化 | 说明、套餐、知识与数据图；HTML、PNG/PDF 等 | 事实正确、手机阅读、导出尺寸 |
| 动画与视频 | 产品演示、概念解释、发布片、解说；源文件、MP4/GIF、音轨 | 帧、节奏、声音与导出 |
| 方向与变体 | 六个候选挑三个真实方向、配色/字体/密度调整 | 方案有实际区别，使用者选择 |
| 评审与经验 | 概念优先的六维评审、事实体检、外观去重、偏好记录 | 工具发现与人工判断分开 |

这些是源码提供的路线，效果取决于模型、素材、需求与环境。本分支不把作者案例当作自己的实测作品。

## 怎么用

在支持 Agent Skills 的宿主导入完整目录，显式调用 `lingchuan-design`。`references/`、`scripts/`、`assets/`、`demos/` 必须保留，不能只复制 SKILL.md。

支持通用 skills CLI 的宿主可尝试：

```bash
npx skills add pail6661/lingchuan-design --skill lingchuan-design
```

该安装和后续导出尚未逐宿主实测。也可克隆完整仓库，按宿主本地技能规范放置；避免同时加载上游与派生版造成触发冲突。

先读取 [SKILL.md](SKILL.md) 和本次模块，确认 Python、浏览器渲染、Node、FFmpeg 等实际能力。开源文件不代表模型免费。WorkBuddy 上传结构、付费资格和云端兼容另验收，本版没有上架或商业可用认证。

需求至少写清：给谁看、解决什么、资料来源、媒介尺寸、必须保留的事实。使用顺序为：**读取已有材料 → 对齐视觉参考 → 六个候选、三个真实方向 → 选定方案 → 完成 → 打开检查、修改和重导出**。

视觉参考对齐是凌川 1.0.1 新增的前置步骤。先读本轮附件、链接、品牌和既有项目；你已指定参考和借鉴点，就直接沿用，不重复索要。缺参考时只温和问一句“有没有想参考的图、网页、演示或视频片段？”；没有则由助手主动找并展示约 2–3 组实际看过的同媒介参考，说明借鉴点和避开点，供你确认。你明确委托助手选参考时可以继续；未回应则保留待确认，不替你批准。

项目只用一份 `visual-reference.md` 记录参考状态（`pending / confirmed / delegated`）、来源、实际看过的程度、借鉴/避开点和原话或依据。参考确认回答“想借哪种视觉语言”，后续方案选择回答“这次用哪个设计”；不反复追问已经说清的事。一般“继续/直接做”不代表选中了某张参考，也不代表跳过三方向。局部改字、机械导出和同项目已确认方向的迭代不重启参考流程；新视觉方向才重开。

无法检索或生图时，可以用实际看过的本地风格样张或自制探针，并标清来源；URL 和文字风格词不能当成已看过的画面。参考用于理解设计语言，不自动授权复制第三方素材。

```text
使用 lingchuan-design，给一家虚构书店做三页社区阅读活动提案。
受众是附近居民，目标是理解活动并决定是否报名。
我会提供文案；缺失的时间地点标注待确认，不补编。
先读本轮资料和已有参考，不重复问已给的信息。
如果没有参考，请展示约2–3组真实可看的演示文稿参考；我明确委托你选择时可记录后继续。
先给真实渲染的设计方向让我选，再做 HTML deck。
如导出 PPTX，检查文字可编辑性和内容有无遗漏。
```

## 当前版本

**凌川 Design 1.0，元数据 1.0.1**：在 1.0.0 整理与探索起点上，新增视觉参考对齐、单文件参考状态记录与不重复询问规则；保留上游六候选到三方向的执行流程。尚未宣称提升视觉质量、全能力跑通或 WorkBuddy 兼容通过。后续以自己的案例和失败记录更新适用范围。详细变更见 [CHANGELOG](CHANGELOG.md)。
