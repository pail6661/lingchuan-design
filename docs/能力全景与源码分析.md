# 凌川 Design 1.0：能力全景与源码分析

审计日期：2026-10-25（Asia/Shanghai）。本报告分析的能力基线为花叔 `huashu-design` 上游提交 **`4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1`**，分支为 `master`。显示名称为凌川 Design 1.0，当前元数据补丁版 **1.0.1**。上游入口的行号固定到该提交；本分支新增的视觉参考对齐另外标明，避免将来源与改动混写。

初次分析完成了源码、目录、依赖声明、测试定义与内部路径检查。**没有安装依赖，没有生成新的设计作品，没有执行浏览器渲染、视频导出、PPTX 转换或云调用。** 1.0.1 追加的是前置流程和说明，真实任务的参考确认、方案生成与交付效果仍待验证。下文的作者案例、作者实测数据和我们后续要做的体验分开记录。

## 1. 先判断它是什么

它是一套供 Agent 阅读和执行的设计工作流：`SKILL.md` 负责路由与交付约束，`references/` 提供媒介方法，`assets/` 提供组件与样张，`scripts/` 负责截图、体检、导出和本地经验记录。它没有自带的大模型服务、后端、账号系统或完整图形设计编辑器。

能力的主体是 **HTML/CSS/JS 视觉表达与浏览器原型**，再通过浏览器和媒体工具导出 PNG、PDF、PPTX、MP4 等。设计质量依赖所用模型、真实素材、任务说明、浏览器工具、人工选择和修改过程；“装上 Skill”不能证明每一类交付已经可用。

上游明确涵盖网页原型、App 原型、演示文稿、信息图、动画视频与设计评审，同时排除生产 Web App、SEO 网站与后端系统。[上游入口 L49–50](https://github.com/alchaincyf/huashu-design/blob/4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1/SKILL.md#L49-L50)

可以对外演示的商业方向包括商家活动说明、产品介绍页、活动信息长图、路演材料、App 交互提案、产品功能演示片和设计评审。实际接单时应把“可点击原型”“静态物料”“可编辑演示”“带声音的视频”逐项写进交付范围；预约、交易、支付、会员、真实 AI 服务等功能需要另行开发和验收。

## 2. 架构与一次任务的流向

```text
用户目标、内容与现有品牌资产
  ├─ 读本机能力、用户偏好、近期外观账本
  ├─ 核实产品事实，收集 Logo / 真图 / 字体
  ├─ 凌川新增：读本轮附件、链接和既有参考，拆借鉴/避开点
  │    └─ 缺参考只温和问一次；没有则助手展示约 2–3 组同媒介可视参考
  │         ↓ 用户确认 / 明确委托选参考；未回应保留 pending
  │       visual-reference.md（作为后续方案共同输入）
  └─ 按输出媒介路由
       ├─ web → modules/web.md
       ├─ deck → modules/deck.md → PDF / 两条 PPTX 路线
       ├─ infographic → modules/infographic.md → 浏览器截图
       ├─ app → app-prototype.md → 多屏可交互展示板
       ├─ motion → modules/motion.md → 三种渲染后端
       └─ critique → critique-guide.md
             ↓
三套思考逻辑，各出两个候选 → 六张真实缩略图 → 三份完整方向稿
             ↓
用户选方向 / 明确豁免，并留下记录
             ↓
结构、内容、素材、组件 → Tweaks → 截图、点击、体检、人工评审
             ↓
源文件 + 指定导出物 + 交付说明
             ↓
本机外观账本、可核验的偏好与经验
```

这里的“艺术总监、品牌研究员、视觉设计师、动效师、前端、文案”是入口提示词分配的角色视角，不是已经部署好的六个独立服务。[上游入口 L30–37](https://github.com/alchaincyf/huashu-design/blob/4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1/SKILL.md#L30-L37) 多 Agent 是可选执行方式，弱环境可以串行降级。[上游入口 L176–188](https://github.com/alchaincyf/huashu-design/blob/4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1/SKILL.md#L176-L188)

### 2.1 凌川 1.0.1 新增：视觉参考对齐

该步骤位于新视觉任务的六候选、三真实方向之前，入口见 [SKILL.md](../SKILL.md)，完整判断统一见 [design-context.md](../references/design-context.md)。它先理解用户已经提供的视觉语言，再把它变成各方案共用的约束；不改变上游媒介模块的交付种类，也不等于新增渲染引擎。

1. **先读已有材料。** 本轮附件、链接、品牌文件、既有项目与已确认选择优先。用户已经指定参考和借鉴点就沿用，不重新索要；多个参考拆为具体借鉴/避开点，只对会影响设计的关键冲突问一句。
2. **缺参考时轻问一次。** 温和询问是否有想参考的图、网页、演示或片段。用户没有则由助手主动寻找并展示约 2–3 组实际看过的同媒介参考，解释各自可借鉴的结构、字体关系、材质或运动语言，供用户确认。
3. **不重复制造确认。** 明确指定的参考可以直接记录为 `confirmed`；用户明确委托助手选参考，记录 `delegated` 和依据后继续。参考确认回答借鉴什么，方案选择回答采用哪份新设计，两者不同；已说清的内容不再问。一般“继续/直接做”不冒充用户选中了某张参考，也不豁免三方向；未回应不是批准。
4. **诚实降级。** 无法检索或生图时，使用实际看过的本地风格样张，或自制/生成的视觉探针并标清来源。URL、文字风格词和文件存在性都不等于已看过视觉；无法确认的内容写明未看、`pending` 或 assumption，不假装已确认。可继续整理事实和内容，不能用待确认信息伪造用户选择。

项目只留一份 `visual-reference.md`，记录以下最小内容：

| 记录 | 用途 |
|---|---|
| 状态 `pending / confirmed / delegated` | 区分待确认、用户已确认和明确委托助手选择 |
| 来源与实际看过状态 | 链接/附件/本地样张/自制探针，以及看到了什么、什么未看到 |
| 借鉴点与避开点 | 转为方案共同输入，不仅写“高级”“简约”等形容词 |
| 用户原话或决策依据 | 证明状态从何而来；助手推断明确标 assumption |

这份记录与 `direction-approved.md` 分工不同，后者仍证明三真实方向展示及方案选择。局部改字、机械导出、同项目已确认方向的迭代沿用现有记录；出现新视觉方向才重新对齐。参考用于理解设计语言，复制第三方图片、品牌、字体、作品布局或其他资产仍须核对权利与范围。此流程写入技能不代表其真实体验已验收。

用户已选参考和品牌连续性优先于外观账本的去重复提示；自由探索时再用账本拓宽候选。现实参照分支可从已观察、获选的本地样张或探针派生候选，不强制再搜两件新作品或调用某个截图脚本；未看见的来源只记待查线索。

## 3. 六类能力：用户给什么、能拿到什么

### 3.1 网页、落地页、Dashboard 视觉原型

| 项目 | 当前源码支持的范围 |
|---|---|
| 用户输入 | 产品/活动目标、受众、真实文案与数字、品牌文件、产品图、参考网址或截图、要演示的操作 |
| 输出 | HTML/CSS/JS 或 React+Babel 原型；三套完整方向 HTML 和截图；选定方向的页面与可选 Tweaks；桌面和手机截图 |
| 可实现交互 | 导航、Tab、展开收起、弹层、选择、表单前端状态、模拟数据切换；具体按钮必须写出状态逻辑 |
| 质量上限 | 可以做高保真界面提案和可操作演示。真实业务数据、权限、安全、SEO、服务可用性不由该 Skill 自动提供 |
| 待实测 | 1440×900 与 375×812 是否溢出；表单和导航是否能点；刷新状态是否合理；字体/CDN/图片离线表现；实际浏览器错误 |

网页模块要求先做完整 HTML 的首屏和全页截图，再做结构、组件与调参，最低正文 14px、移动端正文 16px、点击区域 44×44、对比度 4.5:1，并检查两个视口和交互。[web.md L13–21](../references/modules/web.md) 这些是交付要求，不能因为文档写了就视为已满足。`browser_window.jsx`、`macos_window.jsx` 与 `design_canvas.jsx` 用于展示包装，不增加业务后端能力。[web.md L29–33](../references/modules/web.md)

### 3.2 Deck、PPT、演示与 PDF

| 项目 | 当前源码支持的范围 |
|---|---|
| 用户输入 | 受众、演讲/阅读用途、页数和故事线、真实文案/数据/图、现有品牌模板；客户 PPTX 模板如需继承母版须实际提供 |
| 输出 | 默认先 HTML 演示，再 PDF；用户要求时再走可编辑 PPTX；多页还可生成缩略图、网格或画廊总览 |
| 默认结构 | 多文件：每页独立 HTML，1920×1080，`deck_index.html` 用 manifest 聚合；小型或共享状态强的文稿可用 `deck_stage.js` 单文件 |
| 质量上限 | PDF 能保留浏览器排版与可搜索文本的主要优点；PPTX 可以包含原生文本框与部分形状，但不等于所有视觉效果逐层完整复刻 |
| 待实测 | 全页数量、中文漏字和换行、客户母版继承、PowerPoint/WPS 的字体替换、视觉对照、图表可编辑程度、导出耗时 |

默认交付链和两条 PPTX 路线见 [deck.md L7–18](../references/modules/deck.md)。至少五页先定两页排版语法，三方向阶段每方向做两页代表稿。[deck.md L25–36](../references/modules/deck.md)

两条 PPTX 路线必须提前区分：

1. **从头为 PPTX 写 HTML**：`export_deck_pptx.mjs` → `html2pptx.js` → `pptxgenjs`。画布默认 960×540pt；文本要放在 p/h 标签内；CSS 渐变、文本背景等存在明确限制。[editable-pptx.md L20–67](../references/editable-pptx.md)
2. **已有视觉 HTML 或客户模板**：`pptx_from_rendered.py` 读取浏览器坐标，用 `python-pptx` 建文本与形状，可继承现成 PPTX 的母版/版式/主题，并做文字漏失核对。[pptx-from-rendered-html.md L15–44、L49–72](../references/pptx-from-rendered-html.md) SVG、圆角图等会被栅格化为图片，不能把“可编辑 PPTX”宣传成“所有图形全矢量、所有效果都可逐层编辑”。[脚本依赖与参数 L25–35、L575–588](../scripts/pptx_from_rendered.py)

### 3.3 信息图、长图、活动说明与图文物料

| 项目 | 当前源码支持的范围 |
|---|---|
| 用户输入 | 需要讲清的信息、数据与来源、受众和阅读场景、品牌/产品图、版面尺寸、导出用途 |
| 输出 | 独立可读的 HTML 信息图、三套方向稿与全页截图；浏览器可截 PNG；可保留可修改的 HTML 源文件 |
| 适合场景 | 活动流程、服务步骤、产品对比、知识图解、说明卡、社交平台长图、报告插图、数据关系可视化 |
| 质量上限 | 文字与数据关系可以精确排版，几何图表可编程；真实摄影、复杂商业插画、精确商品展示要有素材或生图能力；不是完整印前系统 |
| 待实测 | 1080px 导出后手机能否读；第一屏是否独立成立；日期/价格/单位是否正确；长图是否切图；平台压缩后清晰度；浏览器截图是否缺字缺图 |

手机信息流默认 1080 宽，首屏 1080×1350；先填真实内容再检查单位和关系，不编造数据。全页 PNG 使用 Playwright screenshot，字号体检默认正文 36px、标签 28px。[infographic.md L7–31](../references/modules/infographic.md)

当前没有独立的“信息图矢量 SVG/PDF 一键转换器”。HTML 中可以含 SVG，截图输出是栅格图；如需 PDF 可另走浏览器打印并核验。**可编辑源文件**在这里指 HTML/CSS/JS，不能当作已交付 Figma、PSD、AI 或其他图形软件原生工程。

### 3.4 App / iOS / Android 交互原型

| 项目 | 当前源码支持的范围 |
|---|---|
| 用户输入 | 用户任务、主流程、4–6 个核心界面、字段/文案/真实内容、品牌与参考、iOS/Android 偏好 |
| 输出 | 默认 4–6 个主界面组成一块有主次构图的展示板，每台手机都有独立状态；单 HTML React+Babel 为常用交付；可给单机完整流程 |
| 可实现交互 | Tab、详情、选择/开关、弹层、局部状态切换；多屏独立状态机，模拟用户任务 |
| 质量上限 | 能演示 App 的外观和部分前端流程；不生成可上架安装包，不自动连接系统能力、真实账号、支付、数据库或推送 |
| 待实测 | 关键三项点击、屏幕状态串联、信息密度、手机框内容裁切、展示板缩放、图片/React/Babel 的加载、离线打开 |

普通 4–6 屏默认单文件内联；超过 1000 行或大型 App 才拆文件并说明需要本地服务。[app-prototype.md L9–23](../references/app-prototype.md) 默认“平铺＋可操作”并不等于等距排一排手机：展示板要求主次、流程或特写，每台宽度不低于 300px。[同文 L57–118](../references/app-prototype.md) iOS 框绑定 `ios_frame.jsx`，Android 有独立框；交付前要求详情、关键标注/操作、Tab 切换的真实点击测试。[同文 L120–163](../references/app-prototype.md)

### 3.5 动效、产品演示片、发布片与带解说视频

| 项目 | 当前源码支持的范围 |
|---|---|
| 用户输入 | 目标受众、片长/比例、内容事实、品牌资产、UI 截图或原型、关键动作/叙事、旁白文本与声音要求 |
| 输出 | HTML 动画、方向关键帧、分镜、导演稿、MP4；可追加 GIF、BGM、SFX；带解说路线另有配音 MP3 与时间轴 JSON |
| 可覆盖题材 | 短动效、UI 功能演示、产品发布片、长概念解说、多屏 UI 画廊、多个分发版本 |
| 质量上限 | 可以做程序化动画和 UI 展示片；3D/粒子等需 HyperFrames、Three.js 等真实后端与适配。长片叙事、美术与混音仍需人工审片；模型配音和云评审另需服务与额度 |
| 待实测 | 首帧、跨场景衔接、持续主体、字幕与旁白同步、每帧是否真更新、音效打点、黑帧/响度、60fps 编码和播放、竖版适配 |

新动画默认 HyperFrames；弱环境或单文件可交付走 Stage+Sprite；带解说长视频走 NarrationStage 自研管线。[motion.md L9–30](../references/modules/motion.md)、[hyperframes-backend.md L8–16](../references/hyperframes-backend.md)

三条渲染路线的区别：

| 路线 | 使用条件与输出事实 |
|---|---|
| HyperFrames | 本仓库提供使用手册和 GSAP 配方，不是已经装好的根依赖。单独建项目并锁版本；暂停时间轴逐帧 seek。文档给出 MP4、透明 MOV/WebM/PNG 序列等输出；这些均未在凌川版本上实测。[手册 L20–43、L63–78](../references/hyperframes-backend.md) |
| `render-video.js` | Playwright 实时录制再用 ffmpeg 编码，录制时钟有约 25fps 限制；不应把转成 60fps 容器当作真 60 帧运动。需正确处理 `__ready` 和录制时的非循环模式。[motion.md L34、L52–55](../references/modules/motion.md) |
| `render-video-seek.js` | 对 Stage/NarrationStage 逐帧调用 `window.__seek(t)`，能按设定 fps 生成独立帧。它不自动驱动任意 CSS 动画、Lottie 或未经适配的第三方动画。[脚本 L3–31、L51–80](../scripts/render-video-seek.js) |

`convert-formats.sh` 默认通过重复帧把视频转成 60fps，插帧是可选项；可追加 GIF。`add-music.sh`、`sfx-cues.sh`、`mix-voiceover.sh` 管 BGM、音效表和配音混音。六首 BGM、37 个 SFX 是现成素材数量，不等于适配每个商业题材或所有渠道的音频授权核验。

所有动画先分镜，≥20 秒有导演稿；≥45 秒的方向确认 Hook 需要手动安装才生效，且无法识别时长时放行，不能宣传为默认强制防返工系统。[motion.md L18–23、L58–60](../references/modules/motion.md)、[design-gate-hook.sh L9–18、L37–50](../scripts/design-gate-hook.sh)

### 3.6 设计评审、风格学习与调参

| 项目 | 当前源码支持的范围 |
|---|---|
| 用户输入 | 实际作品 HTML、截图/设计稿、设计目标、受众、媒介、品牌约束与已知问题 |
| 输出 | 人工/模型评审文字：概念、哲学一致性、视觉层级、细节、功能、创新；保留项、分级问题、修复建议与 Quick Wins |
| 风格学习 | 84 份 HTML 风格样张与对应 JPG，按网页/PPT/信息图/App/中文东亚分区；真实参考截图可聚成 reference board；样张 HTML 可学习 CSS |
| 调参 | 前端 Tweaks 可改主题、字号、密度等，浏览器 localStorage 保存；它不是图形软件式直接拖拽，也不是自动回写源码 |
| 质量上限 | 能给结构化意见与可执行修正方向；审美分数是该评审框架下的意见，不能当作商业转化、专业认证或真实用户研究 |
| 待实测 | 同一份作品评审是否稳定；是否依据截图而非代码猜测；问题是否真实可重现；改后是否更符合 brief；调参是否污染正式导出 |

评审共六维，概念≤5 时总评封顶 6；文档同时有“标题至少为正文 2.5/3 倍”“留白至少 40%”等经验规则，应结合真实媒介和任务判断，不能替代用户需求。[critique-guide.md L9–27、L55–58、L143–180、L184–215](../references/critique-guide.md)

风格库明确要求先看图，并说明样张题材和数字是虚构的；库是没思路时的参考，品牌和内容优先。[design-styles.md L6–19](../references/design-styles.md) 本地偏好学习是经验证据和文字记录，不是模型训练或权重更新。[evolution.md L9–13、L38–53](../references/evolution.md) Tweaks 的刷新保留发生于浏览器存储，不发生于源文件。[tweaks-system.md L3–13、L27–49](../references/tweaks-system.md)

## 8. Windows、Codex、WorkBuddy 与弱环境差异

| 条件 | 影响与应对 |
|---|---|
| Windows PowerShell | `python3` 通常改为可用的 `python`；`$HD`、`export`、`unset`、`NODE_PATH=$(npm root -g)` 等 Bash 示例不能原样当 PowerShell 命令执行 |
| Shell 工具 | 七个 `.sh` 文件依赖 Bash/Unix 文本工具；即使系统能找到 `bash.exe`，也不证明 Git Bash/WSL 中的 ffmpeg、python3 和 Windows 路径已经互通 |
| 中文字体 | macOS 的 PingFang、SF Pro 不等于 Windows 已装字体；HTML 的实际字体、PPTX 的交付字体、客户 WPS/PPT 的替换行为必须分别看 |
| Node 与 Python | 两套 Playwright、浏览器和模块解析独立。全局包装在注释里不代表根依赖已安装；Node 的 ESM 与 CommonJS 解析方式也需实际运行验收 |
| CDN/网络 | 单文件 HTML 可能仍远程加载 React/Babel/字体。`file://`、企业代理、无网环境下必须实测；需离线交付时把许可允许的依赖和素材本地化 |
| 浏览器存储 | Tweaks、页码等可能只在当前浏览器/localStorage 中保存；另一个设备拿到同一 HTML 不一定继承状态 |
| Codex App | 内置生图、浏览器等能力可能不会被 capabilities.py 的目录扫描识别；用真实可用工具补齐，不按探测结果臆断 |

| 并行/子 Agent | 环境没有多 Agent 时可串行。输出质量的关键是实际方向稿和截图，不是 Agent 数量 |

当前检查进程能找到 python、python3、Node、npm/npx、ffmpeg/ffprobe、Bash、uv；Python 可找到 Pillow、python-pptx、requests，**找不到 Python Playwright**。本地无 `node_modules`，从本仓库解析 `playwright`、`pdf-lib`、`pptxgenjs`、`sharp` 都失败。因此当前只能确认源码完整和语法可解析，不能确认生成/导出链已经就绪。

## 9. 网络、数据与许可证边界

“本地核心渲染”指设计 HTML 准备齐全之后用本机浏览器与 ffmpeg 等工具生成文件。素材检索、品牌参考、CDN/字体、依赖安装、更新检查以及所用 Agent 的模型服务仍可能联网；应避免把这句话扩展成“整个使用过程绝对不联网”。[SECURITY.md L7–18](../SECURITY.md) 已列出素材、参考 URL、CDN 与可选云服务；本轮没有对全代码进行安全审计，不应给出穷尽安全保证。

豆包 TTS 发旁白文本，火山方舟 AI 评审发压缩视频段，均使用用户自己的凭据并有 `--yes` / `HUASHU_CLOUD_OK=1` 门。AI 评审模型听不到视频音轨，音效对位主要通过本地 onset 数据与画面核对，不能据此判断音乐情绪或混音优劣。[ai-video-review.md L32–59](../references/ai-video-review.md) 文档中“分钱级”等作者成本描述不等于当前价格与本次费用，需实际账单验证。

本地记忆默认 `~/.huashu-design/experience.md` 与 `ledger.jsonl`，可由 `HUASHU_DESIGN_HOME` 改位置；ledger 含项目绝对路径，偏好可能含用户原话。[SECURITY.md L31–44](../SECURITY.md) 本轮未写入这些记录，也未读取任何 `.env` 的凭据值。

根 [LICENSE L3–13](../LICENSE) 是 MIT，保留原版权和许可文本是分发副本或重要部分的条件；本轮未改 LICENSE。README 还说明品牌资产协议受社区流传的 Claude Design 提示词启发，但没有在这些段落提供该提示词独立的再许可证明。[上游 README L331–346、L412–418](https://github.com/alchaincyf/huashu-design/blob/4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1/README.md#L331-L346) 这项来源说明与“所有参考、商标、字体、照片、音频都可闭源转售”是不同命题。商业交付应保留可追溯的素材来源清单。

## 11. 后续体验与统筹介绍视频需要哪些证据

本报告是能力地图，不替代实际体验。统筹介绍覆盖网页、App、Deck、动画、信息图和贯穿其中的探索、调参与评审，不收窄成单一套餐图。可从一个范围最小的任务验证环境，再按 [总览视频策划](总览视频策划与系列选题.md) 的不同演示 brief 展开。每个新视觉方向先留参考对齐的实际证据，再保留原始输入、环境版本、方向稿、选择依据、失败截图、修改记录和最终导出文件；演示样例与我们生成的文件分别存放。

| 体验方向 | 最小证明 | 视频可讲到的程度 |
|---|---|---|
| 视觉参考对齐 | 实际看过的参考、借鉴/避开点、`visual-reference.md` 的状态及用户原话或委托依据 | 可展示参考如何进入后续方案；未回应和未看清的参考仍如实标记 |
| 信息图 | 同一活动三方向 HTML/截图，选定一版，导出 1080 宽 PNG，手机阅读检查 | 可以展示输入、版式选择、改日期/价格、导出和阅读效果 |
| Web | 至少桌面/手机两视口、真实点击和错误报告 | 可称可操作网页原型；业务后端仍独立说明 |
| Deck | 5 页左右 HTML、PDF、一次真实 PPTX 打开并修改文字；中文逐页对照 | 才能说已体验 PDF 和可编辑 PPTX，并说明哪些是图片 |
| App | 4–6 屏展示板、详情/Tab/关键操作点击录像 | 可称已体验多屏原型；不能称 App 已上线 |
| Motion | 先 10 秒低成本试片，再一段完成音轨与技术检查的成片 | 仅对实际跑通的后端、帧率、声音和格式作承诺 |
| 评审/学习 | 以真实前后作品对照评审、问题定位、调整；验证 localStorage 与私有记录 | 可展示助手如何辅助判断与记住偏好；不称训练出专属模型 |

“全面分析了源码”“作者做过这些例子”“我们在此环境实际生成并验收了”“商家愿意付款并已回款”应作为四层独立证据。介绍视频可以讲清这四层差别，把探索过程、限制和有用的结果一起呈现。
