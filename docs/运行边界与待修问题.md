## 1. 配音环境模板与实现协议不一致

**程度：P2。状态：静态确认配置不一致；未调用接口验证报错形式。**

源码证据：

- `.env.example:6` 配置 `/api/v1/tts`。
- `scripts/cloud/tts-doubao.mjs:195` 的默认端点为 `/api/v3/tts/unidirectional`；`206–225` 行构造 v3 请求，`232` 行使用 v3 流式响应解析。
- `scripts/cloud/tts-doubao.mjs:41–58` 会加载根目录 `.env`，`195` 行优先使用环境端点。照抄模板会覆盖正确的默认值。

影响：用户按模板配置后，可能遇到协议或响应解析失败；不能把配音列为本机已可用。旧 `DOUBAO_TTS_CLUSTER` 配置也不应被误解为当前实现读取的必要字段。

建议修法：模板与当前 v3 实现统一；音色、资源 ID 与鉴权按自己的账号条件核对，清理不再读取的配置。不要通过改成任意第三方端点绕过实现中的域名白名单。

验证方法：先静态核对模板、默认端点、请求体和响应解析属于同一协议；之后如需实测，使用自己的账号和一句无隐私测试文案，确认得到可播放音频及真实用量。接口调用、费用和成功回执分别记录；此处尚未执行。

## 2. 视频录制默认隐藏规则可能误删正文

**程度：P2。状态：静态确认规则过宽；尚未用本分支作品复现误隐藏。**

源码证据：

- `scripts/render-video.js:77–87` 默认隐藏 `.title`、`.footer`、`.phase`、`.counter` 等通用类名。
- `scripts/render-video-seek.js:66–78` 使用相同规则，两条录制路线均受影响。

影响：具有这些类名的作品标题、页脚信息或阶段正文，可能在正常浏览时存在、导出视频时消失。不能只验收浏览器页面或编码成功日志。

建议修法：默认只隐藏明确的录制标记，例如 `[data-record="hidden"]`；逐步兼容确有必要的旧控件。修复前可使用 `--keep-chrome` 保留内容，再对确实不应入镜的控件做明确处理。

验证方法：未来建立含 `.title`、`.footer`、`.phase` 正文和显式录制隐藏控件的本地短样例；比较浏览器、默认导出与 `--keep-chrome` 导出的关键帧。应保留正文，只隐藏明确控件。录制路线分别检查，不能只测其中一个脚本。

## 3. 配音管线会清理非唯一的输出子目录

**程度：P1。状态：静态确认存在误删既有文件的条件；未实际触发删除。**

源码证据：

- `scripts/narrate-pipeline.mjs:202–207` 将临时目录固定为用户指定 `outDir` 内的 `.tmp`，允许复用已有目录。
- `scripts/narrate-pipeline.mjs:348` 对该目录执行递归强制删除。

影响：若所选输出目录原已有其他用途的 `.tmp` 内容，成功运行后的清理会将其一并删除。不能笼统声称所有删除对象均为本次创建的唯一临时目录。

建议修法：创建唯一临时目录，保存其实际路径并只清理本次所有的目录；异常清理也保持同一边界。未修复前，整条配音管线只使用全新专用输出目录，不复用用户已有项目目录。

验证方法：修复后以隔离目录中的无价值哨兵文件做回归检查，确认同级预存 `.tmp` 内容保留；用 mock 的 TTS/FFmpeg 或独立清理测试验证，避免为了检查删除而产生云调用。此项不要在真实用户文件上试删。

## 4. 成功退出或生成文件不等于完整验收通过

**程度：P2。状态：静态确认多种状态被混用；尚未完成媒体验收。**

源码证据：

- `scripts/design_lint.py:246–252` 缺少 Python Playwright 时打印“体检跳过”，但 `sys.exit(0)`。自动化仅看退出码会把未执行误判为通过。
- `scripts/export_deck_pptx.mjs:94–104` 仅在全部页面失败时退出 1；部分页面失败仍生成 PPTX，并在日志中标明成功页数。文件存在不证明页数完整。
- `scripts/verify.py:101–119` 仅将页面脚本异常作为失败条件；控制台警告与错误被打印，但不改变成功退出状态，也未代替人工视觉检查。
- `scripts/verify.py:60` 固定 `device_scale_factor=2`。视口尺寸与截图像素尺寸不是同一指标，1080×1350 视口按该配置产生的普通截图预期为 2160×2700，尚需测量实际交付文件。

影响：可能把缺依赖、部分导出或仅无脚本异常的结果宣传为“已通过”；也可能把文件名或视口参数当成最终图片规格。

建议修法：自动化明确区分 skipped、partial、passed；部分导出默认失败，或要求显式允许后提供失败清单；截图支持明确的输出倍率。保留人工看图、内容核对、真实编辑和播放验收。

验证方法：未来分别构造缺依赖、三页中一页不合规、存在控制台错误、固定视口截图四类受控用例；检查状态、日志、实际页数和实际像素。PPTX 还应打开文件确认文字编辑及视觉保真。`pptx_from_rendered.py:14–18` 明确 SVG 以图片处理，不能宣传“任意 HTML 全元素可编辑”。

## 5. Windows 完整交付链仍待适配与实测

**程度：P2（环境兼容待确认）。状态：有明确平台依赖；不将待验证路径写成已复现故障。**

源码证据：

- `scripts/render-narration.sh:1` 是 Bash 入口，`115–125` 行使用 `NODE_PATH=$(npm root -g)` 等 Bash 语法；不能直接当作 PowerShell 命令。
- `package.json:2–7` 只声明 Node 包；Python 包、Chromium 浏览器及 FFmpeg 需分别确认。本机缺 Python Playwright 的测试结果已说明依赖并非全部就绪。
- `scripts/html2pptx.js:919` 默认临时目录为 `/tmp`；`936` 行手工拼接 `file://`。其他导出入口也有同类文件 URL 构造，如 `scripts/export_deck_pdf.mjs:65`、`scripts/pptx_from_rendered.py:250`。

影响：语法检查通过不代表原有 Bash 配方可以直接在 Windows 完成制作、混音与导出；中文、空格、井号等路径和临时目录行为需要验证。手拼 URL 是兼容性检查点，此审查没有证明它在所有 Windows 路径上均失败。

建议修法：提供 PowerShell 入口或明确 Bash 运行条件；统一采用系统临时目录与标准文件 URL 转换；依赖探测覆盖实际导出所需组件。先完成一次最小链路，再扩展到全部媒介。

验证方法：使用 F 盘独立目录，覆盖中文、空格和特殊字符路径；分别检查截图、PDF、两类 PPTX 路线、无声视频及混音。核实文件可打开、页数与时长正确、声音和字体正常。没有实际完成的路线继续标为待验证。

## 无安装、无云调用的轻量检查

以下检查不执行业务脚本主体、不安装依赖，不证明媒体运行成功：

```powershell
python -B -X utf8 -c "import ast,pathlib; ps=sorted(pathlib.Path('scripts').rglob('*.py')); [ast.parse(p.read_text(encoding='utf-8-sig'),filename=str(p)) for p in ps]; print('Python AST OK:',len(ps),'files')"

$files = Get-ChildItem -LiteralPath scripts -Recurse -File | Where-Object { $_.Extension -in '.js','.mjs' }
foreach ($file in $files) {
    node --check $file.FullName
    if ($LASTEXITCODE -ne 0) { throw "语法检查失败：$($file.FullName)" }
}
```

`python -B -X utf8 scripts/capabilities.py --json` 可额外读取技能目录、工具及浏览器安装状态，输出可能含本机路径和密钥变量是否存在，不输出密钥值；它不安装缺失组件。完整回归测试会读写临时文件、部分用例启动浏览器，不属于纯静态检查。不要把 `npx` 安装、浏览器下载或云接口调用夹在“无副作用自检”中。
