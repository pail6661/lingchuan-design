# 三方向：三种好设计，不是三种皮

任何新视觉设计，先出三个方向的真实初稿给用户选。这道门本身不变：100% 触发、指定风格或品牌也不豁免、摆出来就停、选择落档 `direction-approved.md`（豁免条件见 SKILL.md「窄桥」）。

这份文件讲**三个方向怎么生成**。进入六候选前，先按 `references/design-context.md` 对齐视觉参考；后续三方向是在该范围内做本任务的方案，不是再让用户选一次同样的参考。

## 为什么这样做（三轮问题与盲选的结论）

**第一轮问题：三版只换了皮。** 三版常常是同一个骨架换颜色和字重。差异要落在版式结构上，不是配色上。

**第二轮问题：隐喻用力过猛。** 强制每版先定一个「大想法隐喻」，页面被整个做成档案柜、借书卡、地铁线路图，用户盲选 4 题输 3 题。

**第三轮问题：约束太多，变无聊。** 为了避开「AI 默认外观」，曾经限制三版里最多一版暖纸衬线，并把深底单点缀、细线报纸这些外观家族列成黄灯。结果三版一起退到浅冷色、规整网格，用户说「太规整，太无聊了」，又输给了不加这些约束的旧做法——而旧做法里他认可的几版，恰好就是深底单点缀、暖纸衬线。

所以现在的做法是**加选项，不加禁令**：三套逻辑照旧，每套出两个候选、先画六张缩略图，挑最强又有实质区别的三张做完整版；风格从看得见的样张里选，参考从已观察的画面里拆。自由探索时用外观账本避免惯性，用户已选参考、品牌体系和同项目延续优先；三版可以共享已确认语言，差异落在内容结构与表达上。

## 流程

### Phase 1 · 读已有材料＋视觉参考对齐

先读本轮材料和本项目已有确认，已知的受众、内容、尺寸、品牌资产与参考不重问。缺项从 `references/workflow.md` 题库合并提问，通常最多 3 个，优先补真正改变结果的信息。

视觉参考的判断与表达统一按 `references/design-context.md`：已有明确参考就观察、提炼并沿用；未说明则温和问一次；明确没有就主动展示适合媒介的可看参考供选择。当前附件只有内容/数据时，不误记为视觉已确认。

进入六候选前，项目 `visual-reference.md` 应已有 `confirmed` 或明确委托的 `delegated` 依据；`pending` 时可查事实、整理文案与素材、展示参考或探针，但不自行选中参考进入新视觉稿。用户未回应不等于批准。局部改稿和非设计机械操作沿用 SKILL.md 的豁免，不重新开题。

给了具体品牌或产品名（能去官网找到 logo 的那种）→ 加走品牌资产协议（`references/brand-asset-protocol.md`），三个方向全部基于同一套真实资产，差异在诠释。普通主题名（咖啡、历史、健身）不是品牌，别去找「咖啡的 logo」。

### Phase 2 · 顾问式重述

参考已经对齐后，用自己的话重述本质需求、受众、场景、基调以及已确认的借鉴/避开点；推测的期待标为假设，不冒充用户原话。说清“接下来用你的内容做三个有区别的真实方案”。此时不再让用户选择抽象风格词；尚未对齐参考就先完成上一步，不直接承诺开做三稿。

### Phase 3 · 固化 spec

写一份设计 spec，作为三个方向的共同输入：项目、受众与场景、核心内容、基调、**输出格式与尺寸（必填，三版统一）**、已知约束、图片需求，并引用 `visual-reference.md` 的已确认借鉴/避开点与品牌规则。共同约束写清楚，具体骨架和表达由方向卡探索；不要让每版偷偷换内容或越过参考范围。

### Phase 3.5 · 素材前置

按 `references/materials.md` 先判档位、取齐内容必需的真图和具名产品的 logo，三个方向共用。

### Phase 4 · 六个候选 → 六张缩略图 → 挑三张

开写之前先复用 `visual-reference.md` 中的观察和约束，不为同一参考重新检索或再次确认，再看本机经验与样张：

```bash
# $HD = 本 skill 的根目录（SKILL.md 所在目录），不是用户的项目目录
python3 "$HD/scripts/learn.py" direction color <题材关键词>   # 这个用户的偏好＋过去的教训
python3 "$HD/scripts/design_lint.py" ledger                     # 提醒自由探索避免惯性；用户已选参考/品牌延续优先
```

再用看图能力打开风格总览：`$HD/assets/style-specimens/sheet-<分区>.jpg`（分区：web / ppt / info / app，外加跨媒介的 east 中文与东亚）。一张图里是这个分区全部风格的样张，先知道每个风格做到位是什么样。

**4a · 三套逻辑，每套出两个候选（共六个）：**

- **最佳设计师 ×2**：深呼吸，认真想——假如预算没有上限，世界上最适合为「这个用户、这个题材」做设计的工作室或设计师是谁？想出两位气质不同的（一位大胆、一位克制；或一位西方、一位东亚）。启用他的设计思维从头做，不模仿他某件作品的外观。别总是同几个名字：Pentagram、原研哉、Vignelli 之外，还有吕敬人、杉浦康平、田中一光、服部一成、Irma Boom、Experimental Jetset、Collins、Studio Dumbar……
- **现实参照 ×2**：优先复用 `visual-reference.md` 中实际观察且获选的参考，从中派生两个不同的方案候选，不要求为凑两个候选再找两件新作品。需要补充时优先找同媒介真实作品并看画面；跨媒介启发需说明可迁移和不能迁移的部分。检索不可用时，已获选的本地样张或自制/生成探针同样可以作为依据，按真实来源命名。工具按当前能力选用，`ref_board.py` 仅是可选的参考板路线：

  ```bash
  python3 "$HD/scripts/ref_board.py" <作品网址或图片网址> [<第二个>] --out refs/board.jpg
  ```

  用看图能力打开参考板或原图，把借的东西写成具体规则：网格几栏、标题和正文字号比、主色占比、图文关系。截不到（反爬、WebGL 黑屏）就换已见过的来源或已获选样张；仍未看到的只记为待查线索，不能据此拆视觉规则或当作正在使用的来源。
- **秒数轮盘 ×2**：取当前秒数 S（`date +%S`；Windows PowerShell 用 `(Get-Date).Second`），从 `references/design-styles.md` 对应分区抽 `S % 分区风格数 + 1` 号，再从 east 分区抽 `S % 12 + 1` 号。编号就是条目在分区里出现的顺序，和样张文件名、总览图格子上的编号一致。先打开抽到风格的样张图（条目里的「样张」一行），看清它做到位的样子再写卡。自由探索时撞外观账本最近 3 个交付可顺延；若是用户已选参考或品牌延续则保留并说明复用理由。还原度不足标注降级部分，轮盘不能越过共同约束。

**用户指定了参考、风格或品牌时**：六个候选都服从已确认的共同约束，颜色可以都受品牌约束（compare 加 `--brand`，只比骨架）；现实参照优先复用已经实际看过的作品，确需补充时说明用途，不自动推翻用户选择。轮盘只在可兼容的样式里抽，不能为差异回到用户明确排除的颜色/密度/形式。「Apple 风格」是一个语境不是一个设计。

**4b · 写六张方向卡**，写进项目目录的 `directions.md`，每张一段：

| 栏 | 写什么 |
|---|---|
| 逻辑与来源 | 哪位设计师 / 哪个作品（附出处和参考板路径）/ 抽到几号哪个风格 |
| 共同参考约束 | 对应 `visual-reference.md` 的哪条借鉴/避开点；与用户已选参考怎样保持一致 |
| 借的是什么 | 从来源里拆出来、要用到这次设计上的具体规则：网格、字体关系、色彩比例、图文关系 |
| 主角素材 | 画面主角是什么：真图、生成图、程序化材质、数据图像、巨字……（档位见 `references/materials.md`） |
| 骨架 | 版式结构一句话 |
| 胆量花在哪 | 唯一一处最大胆的地方，其余服务内容 |
| form 来自内容的哪里 | 一句话：这个设计里哪个东西是这个题材才有的 |

**4c · 画六张缩略图。** 一个 `design-demos/thumbs.html`，六格，每格是这个候选最关键的一屏（网页首屏、deck 封面、信息图开头、App 主屏），约 480×300：真字体、真配色、真骨架、真标题，细节可以省。截图后用看图能力看。缩略图很便宜，这一步就是用来多试几种风格的——一张缩略图看着不对，换来源重画这一格，不用等做完整版才发现。

**4d · 挑三张做完整版**，标准按顺序：

1. **单看就够好**：拿出去不丢人。缩略图都撑不住的，完整版也救不回来。
2. **三张彼此不一样**：骨架不同、气质不同（大胆／中性／安静不必凑齐，但别三张都同一温度）、不挤在同一个外观家族。
3. **自由探索时避免惯性重复**：账本提醒拓宽选择；用户已选参考、品牌体系和同项目延续优先，明确记录有意复用，不为“新鲜”推翻选择。
4. **不用力过头**：把整页做成道具或实物仿制、套万能隐喻（地铁线路图、终端命令行、报纸头版、仪表盘）、饱和度字号全部拉满——三张里最多一张这样，而且只在内容真需要时。判断方法：**把这个手法去掉，信息是更清楚还是更糊？** 去掉反而更清楚，它就是过头。

三张不必一套逻辑各一张：两张最佳设计师加一张轮盘也可以，选最强的。没选上的三张留着，展示时一起给用户看。

一个例子（题材：一家做了三代的手工酱油厂官网）：

- 最佳设计师｜原研哉｜借的：大量留白、素材本身做主角、极少的字｜主角：陶缸与晒场的真实照片｜骨架：一屏一张图一句话，纵向慢节奏｜胆量：首屏一整张盐霜特写｜form：酱油要晒 180 天，节奏就放慢
- 现实参照｜一个获过奖的日本老字号食品官网（附截图）｜借的：竖排标题与横排说明的关系、两色的比例、细框分区｜主角：产品瓶身实拍＋竖排标题｜骨架：左竖排标题、右三栏内容｜胆量：只用两种色｜form：老字号的「方子」气质
- 秒数轮盘｜抽到「媒体级粗野主义」｜借的：大字号反差和模块网格｜主角：超大汉字「酱」切进首屏｜骨架：模块网格，图文交错｜胆量：首屏字号反差｜form：一个字讲完一家酱园

### Phase 5 · 并行构建，每版自检

每个 subagent 只拿 spec（含已确认参考约束）＋ 自己那一张方向卡（含实际参考板或样张图）＋ 共用素材，独立 context、互不参考。不支持 subagent 的 runtime 串行做，每版开工前只读共同约束和自己的卡，不参考已做的版本。只传相关且允许使用的素材，不把私人项目记录复制到公共技能目录。

构建规则（三版共用）：

- 用户真实内容，不用 Lorem；三版同内容只换设计
- 可读性硬底线：网页正文 ≥14px、标签 ≥12px；deck 正文 ≥24px、标签 ≥16px；手机看的 1080 宽长图正文 ≥36px、标签 ≥28px；正文对比度 ≥4.5:1；留白要是构图，不是内容缺席
- 单文件 HTML；单文件交付时图片和 logo base64 内嵌
- deck 用 deck 外壳，每方向出 2 页代表页（`references/modules/deck.md`）
- App 原型的多屏不要只排成一排手机，展示板构图见 `references/app-prototype.md`「展示板」
- 缩略图存 `design-demos/thumbs.html`，三个完整版存 `design-demos/dir-1.html`、`dir-2.html`、`dir-3.html`（deck 是 `dir-1/` 等子目录），截图 `npx playwright screenshot file:///… out.png --viewport-size=1440,900`（deck 用 1920,1080）

三版都做完后跑：

```bash
python3 "$HD/scripts/design_lint.py" check design-demos/dir-*.html       # 红灯必修；黄灯是顺手的模板装饰，删掉；外观家族只是提示
python3 "$HD/scripts/design_lint.py" compare design-demos/dir-*.html     # 两版撞了 → 换成备选里的另一张，或换骨架，不是换颜色
#   品牌约束了颜色字体加 --brand；App 原型多台手机并排加 --ignore-layout；deck 加 --viewport 1920x1080 --min-body 24 --min-label 16
python3 "$HD/scripts/design_lint.py" ledger check design-demos/dir-*.html # 撞惯性时调整；已选参考/品牌延续则记录有意复用
```

完整版命名 `design-demos/dir-1.html` 到 `dir-3.html`，确认真有 3 个再往下。黄灯删掉那个结构就好，换个符号躲过检测不算改；外观家族不用改，它只在三版挤在一起、或撞了账本时才有意义。没装 Python 版 playwright 时脚本会跳过并提示安装，这时用截图肉眼对照三版，并把这件事写进交付说明。

### Phase 6 · 展示，然后停

一起摆出三张完整版截图，每版附它的方向卡摘要（逻辑与来源、借的是什么、主角素材）和一句「form 来自内容的哪里」；再附上缩略图总览，说一句「另外三张是备选，看中哪张我做成完整版」。摆出来就结束这一回合等用户选，包括无人值守会话。

### Phase 7 · 用户选了之后

- 把「展示了哪几版、截图路径、用户的原话」写进 `direction-approved.md`
- 用户的话里有对品味的明确表态，先在本项目保留原话和适用范围；只有用户说明是长期偏好并同意记录时，再用 `learn.py add --kind preference` 写入本机品味档案
- 混合选择（「A 的布局＋C 的颜色」）照做，记下他混的是哪两栏——这比记住他选了哪个颜色有用；他说某版「过头」「太素」也逐字记下
- 进入执行；交付后 `design_lint.py ledger add <最终文件> --project <名字> --note "<来源：设计师/作品/风格；有意复用的理由>"` 记一笔外观账，帮助后续自由探索避免惯性，不否决用户指定的复用
